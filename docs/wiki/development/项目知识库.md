# BetterGTExperience 项目知识库

## 项目定位与事实边界

这是全新 GTNH 附属项目，根包 `com.day.betterexperience`，模组 ID `betterxeperience`。迁入的热核项目文档不代表本项目已实现功能；原知识库保存于[归档](../archive/development/迁入热核项目知识库.md)，仅用于按需追溯。

当前源码包含通用多方块基类与地狱接口复刻。基类支持普通及特殊能源输入、长整型耗电、标准配方处理、并行与超频扩展、创造／生存建造接口，默认免维护；无线支持仅保留 TODO，没有无线供电实现。地狱接口保留 TST 的原结构、随机产物机制与运行配置，并禁用原机不支持的处理选项。

- 旧 Thaumcraft NEI Plugin 的 CurseMaven 包通过 `runtimeOnlyNonPublishable(rfg.deobf(...))` 显式登记，将传递依赖中的 SRG 调用转换为开发环境 MCP 名称；不移除插件或改变版本。

- `BGTEMultiblockBase.depleteInput(ItemStack/FluidStack, long, boolean)` 为自定义配方提供跨栈精确扣料、模拟与不足不扣料，省略布尔参数即实际扣料；数量独立于模板栈大小，负数抛异常。仅在 GT 配方处理生命周期内使用，沿用普通输入集合及 ME 去重，不合并合成缓存分组；单种 ME 快照仍受 `int` 限制。多个材料的调用不构成整体事务，需由调用方先统一校验；标准配方继续复用 GT5U 的长整型总需求计算。
- 自定义并行产出先用 `long` 计算总量，再由 GT 原生 `ParallelHelper.addItemsLong/addFluidsLong` 拆分并写入输出数组；地狱接口已接入，耗水余量也使用 `long`。单栈与并行次数仍为 `int`，拆栈不提供输出空间校验；API 与数量截断陷阱见[长整型并行产出](../references/GT-Not-Leisure参考索引.md#长整型并行产出)。

## 蒸汽工业电解机

- 实现位于 `src/main/java/com/day/betterexperience/common/machine/multiblock/SteamIndustrialElectrolyzer.java`，公共蒸汽层为同目录 `base/BGTESteamMultiblockBase.java`，材料等级由 `base/SteamMachineTier.java` 定义。青铜基础为 16 并行、1 倍速度，钢基础为 32 并行、1.5 倍速度，禁用按配方电压自动超频。GUI 右侧按钮打开 0–4 次手动超频输入框，默认 0；每次使单 tick 耗汽乘 4、处理时长除以 2，与材料速度叠加，沿用 GT 的整 tick 下限。该设置双向同步并写入 NBT，按 GTNL 原行为仅在同步和倍率计算中限制上界为 4，读档直接赋值，不添加额外下限校验，不加入主机 Tooltip。
- 蒸汽基类默认配方上限为 MV。电解机每次通过 `getTierRecipes()` 读取控制器物品槽，与 GT 原生不锈钢齿轮比较；放入齿轮时为 HV，空槽或其他物品为 MV，不消耗齿轮，不改动材料等级、并行与速度。
- 主机说明存放于 `src/main/resources/assets/betterexperience/lang/{zh_CN,en_US}/tooltip/steam-industrial-electrolyzer.md`，由 GT 原生 `MultiblockTooltipBuilder.addMarkdown(ResourceLocation, Map)` 加载；并行和速度变量取自材料枚举。结构页保留原生 Builder，输入／输出总线分别使用 `addInputBus`、`addOutputBus`，仓口提示编号为 1。D 位同时接受蒸汽供给仓、蒸汽和普通输入／输出总线、流体输入／输出仓；普通总线可替代对应蒸汽总线满足成型要求，火箱仍不可替换。普通物品输入保留真实栈、颜色过滤和 ME 去重，输出与槽位更新同时覆盖两类总线。两台 TST 移植机器不迁移 Markdown。
- WAILA 通过 `getExtraWailaBody` 补回原生最大并行／并行覆盖显示，复用 GT 已同步的 `maxParallelRecipes`、`powerPanelMaxParallel` 与语言键。GT5U `.265` 蒸汽基类重写正文且不调用普通多方块正文，因此原生最大并行行不会自动出现；保留蒸汽耗量、进度及未成型提示，不重复整份正文。
- 蒸汽基类支持 MUI2 的 Input Separation 与 Batch Mode，新机器两者默认关闭，切换同步、立即安排配方检查及 NBT 保存复用 GT。输入分离时，`checkRecipeForCustomHatches` 在原生合成缓存检查后逐个匹配蒸汽输入总线，再交回 GT 检查普通总线；不合并不同总线的物品，流体按颜色共享，控制器槽遵循 `canUseControllerSlotForRecipe()`。关闭分离时合并普通／蒸汽总线，控制器槽统一由 GT 加入，避免电路重复计入。批处理直接沿用原生 `setupProcessingLogic`／`ParallelHelper` 的批量扣料、产出和延长时长，不增加瞬时并行或另定倍率；实际批量受原生批次上限、时长、材料与输出空间限制。尚未进行游戏内验收。
- 参考 GTNL 的 [Tooltip 与仓口](../references/GT-Not-Leisure参考索引.md#tooltip-与仓口) 条目；当前本地蒸汽离心机只有 MV 配方上限，不锈钢齿轮逻辑实际位于蒸汽搅拌机。手动超频取公共蒸汽基类／GUI 的 0–4 次规则，不迁入搅拌机专用性能公式、GTNL 扩展处理器或无线蒸汽网络。
- 本次 API 核对使用当前 `build/elytra_conventions/2.9.0.json` 指定的 GT5U `5.09.54.265` 缓存源码；旧 `2.9.0-RC-2`／`.205` 为历史解析结果，不代表当前依赖已重新解析。未运行编译或游戏验收。

## 单元毁灭者电解机

- 实现为 `src/main/java/com/day/betterexperience/common/machine/singleblock/CellDestroyerElectrolyzer.java`，沿用现有 `ElectricLatex` 的 `MTEBasicMachineWithRecipe` 注册／实例构造方式；只注册 LV、MV、HV、EV 四档，按既有 `32200` 起始序列追加在过胶机之后，不移动已有 ID，不依赖 TST。`BGEMachineList` 提供四档机器引用。
- 制造配方由 `MachineRecipes.registerCellDestroyerElectrolyzerRecipes()` 在 load-complete 注册，每次产出一台。图案为 `TGT / TMT / CWC`：T 为四个同档储罐，LV 使用 BuildCraft `tankBlock`，MV／HV／EV 分别使用 Iron Tanks 的 `copperTank`／`ironTank`／`goldTank`（EV 已由用户确认改为金储罐）；G 固定为 GT 防爆玻璃 `ItemList.ReinforcedGlass.get(1)`，不再使用 IC2 `reinforcedGlass`，M 为同电压等级 GT 电解机，两个 C 通过矿辞匹配同等级电路。W 为一根 16x 包裹线缆，四档分别为锡／铜／金／铝；铜沿用原机的 `AnyCopper` 矿辞匹配。此处 `OrePrefixes.get` 仅提供合成台矿辞材料描述，不作为 `ItemStack` 获取 API。
- 使用 `RecipeMaps.electrolyzerNonCellRecipes`，物品槽为 6 输入／6 输出，流体槽为 1 输入／6 输出；GUI 明确限制为单个流体输入槽。保留原生配方电压限制、耗电、普通超频和输入检查，不复制配方或增加并行。外观覆盖层与工作音效取 GT 原生电解机，储量沿用 `getCapacityForTier`，六个输出槽各自拥有完整容量。
- 机器显示名在基础名称后追加等级罗马数字：LV 为 I、MV 为 II、HV 为 III、EV 为 IV；注册等级仍使用原生电压等级。
- 原生基类只检查、抽签并提交流体产物 0。本机通过 `canOutput(GTRecipe)` 在扣料前逐槽检查全部流体的类型与容量；`checkRecipe(boolean)` 保留原生第 0 项概率结果，并对剩余产物各抽签一次，清空原生单流体缓冲，防止重复产出。`endProcess()` 在原生进度真正完成时一次性提交六个待产物流体槽；当前储液和已抽签待产物均逐槽保存到 NBT，断电停顿不提前输出，`abortProcess()` 清理待产物。
- `getTankInfo` 暴露输入槽和全部六个真实输出槽；无类型抽取使用轮询选中的输出槽，指定类型的 `drain` 支持所有输出槽并区分流体 NBT，模拟抽取不修改存量。沿用原生每次最多 1000 mB 的自动输出流程，每 20 tick 轮换首选槽，避免首个受阻流体一直挡住其余产物；抽取后标记库存变化，触发配方重查。
- 界面为 `src/main/java/com/day/betterexperience/client/gui/CellDestroyerElectrolyzerGui.java`，在 GT 原生 MUI2 单方块界面中增加两行六个流体输出格，逐格绑定独立 `FluidStackTank` 与同步处理器，禁止向输出格灌液；保留输入流体格、物品输出、幽灵电路和自动输出按钮。槽位材质与两套进度条均取原版电解机：首个物品输入使用充电图标、其余物品输入使用容器图标，流体输入使用流体充电图标，物品／流体输出不加覆盖图标；NEI 跳转仍指向无单元电解配方池。
- API 依据 `build/elytra_conventions/2.9.0.json` 指定的 GT5U `5.09.54.265` 缓存 sources JAR 核对。GTNL 检索边界及复用方式见[单方块多流体输出参考](../references/GT-Not-Leisure参考索引.md#单方块多流体输出)；未重新解析依赖，编译和游戏内多产物、堵塞、管道、容器取液及重载存档尚未验收。

## 单元毁灭者搅拌机

- Tooltip 中英 Markdown 的局部颜色沿用蒸汽电解机的 `{yellow:9}`／`{aqua:6}` 命令，不直接写 `§` 颜色码。蒸汽版保留用户指定名称“青铜蒸汽搅拌机”／“高压蒸汽搅拌机”，不据此判断注册问题。静态注册入口已有 `32220`／`32221` 的构造及枚举绑定，本次未改机器 ID 或注册逻辑。
- GUI 物品输入／输出槽使用 GT 原版搅拌机粉末图标，蒸汽档使用青铜／钢对应粉末图标；流体输入／输出槽按 GT 原版不加覆盖图标。蒸汽回调返回 `SteamTexture.NONE`，保留父 GUI 对 `.get(tieredVariant)` 的调用安全。编辑素材位于 [`dev/gt-textures/`](../../../dev/gt-textures/README.md)，仅供用户编辑，不接入运行时资源；包含两种机壳、组装机共用覆盖层和电力搅拌机覆盖层／动画描述。
- 新增青铜蒸汽、钢蒸汽、LV、MV、HV、EV 六档，用户确认按此顺序占用 `32220–32225`，不移动已有机器 ID。注册入口为 `registry/MachineLoader.java`，统一引用为 `BGEMachineList.CellDestroyerMixer*`。
- 六档制造配方由 `MachineRecipes.registerCellDestroyerMixerRecipes()` 在 load-complete 注册，每次产出一台，图案统一为 `TRT / TRT / CMC`。四个 T 为储罐，两个 R 为转子，两个 C 为电路或箱子，M 为原机或砖砌外壳。电力 LV／MV／HV／EV 的储罐沿用电解机配方，依次为 BuildCraft 普通储罐、Iron Tanks 铜／铁／金储罐；转子依次为锡／青铜／钢／不锈钢，C 为同档电路矿辞，M 为同档 GT 搅拌机。蒸汽两档均使用普通储罐和原版箱子，青铜档为青铜转子及 `Hull_Bronze_Bricks`，钢档为钢转子及 `Hull_HP_Bricks`，外壳与过胶机配方一致。缺失储罐、转子或原机／外壳时记录并跳过该档，注册返回值按档记录；配方尚未进行编译或游戏内合成验收。
- 电力机实现为 `common/machine/singleblock/CellDestroyerMixer.java`，蒸汽机为同目录 `SteamCellDestroyerMixer.java`；共享储液和配方处理位于 `CellDestroyerMixerFluids.java`。直接使用 GT 多方块搅拌机的 `RecipeMaps.mixerNonCellRecipes`，提供 9 个物品输入、9 个物品输出、6 个流体输入和 6 个流体输出，不复制配方池或增加并行。
- 各输入／输出流体槽均有独立真实储液罐。配方匹配和扣料传入完整输入数组，扣料前检查所有输出槽的类型、容量及空输出要求；按概率保存六项待产物，完成时提交，终止时清理。输入、输出和待产物逐槽写入 NBT；原生单流体待产物保持为空，防止重复提交。
- 流体接口暴露全部真实储槽，指定类型抽取按流体和 NBT 匹配，模拟抽取不修改存量；无类型抽取轮询输出，复用原生自动输出时机和转移上限。两种 GUI 均将六个输入格和六个输出格绑定真实储槽，输出格禁止灌液。蒸汽 GUI 保留原生蒸汽表、排气错误提示，并增加流体自动输出开关。
- 电力档沿用原生等级容量和超频；蒸汽档每个配方储槽为 16000 mB，青铜按 LV、钢按 MV 查询配方，沿用原生蒸汽超频描述器、供能缓冲与排气机制。动力蒸汽不进入配方输入槽，因此蒸汽版不将动力蒸汽作为配方材料。电力档保持 GT 电力搅拌机外观；蒸汽档按材料选择 GT 青铜／钢的顶、侧、底机壳，以原生染色叠加现有搅拌机前／侧／顶 Overlay 和工作态动画。底面仅使用机壳，不引用不存在的底面 Overlay 或发光层；排气面在对应朝向机壳上叠加原生管口。运行时不复制或生成新材质，`dev/gt-textures/` 仍为参考素材。Tooltip 使用中英 `tooltip/cell-destroyer-mixer.md`。
- API 按当前 `2.9.0` 清单对应的 GT5U `5.09.54.265` 缓存 sources JAR 核对，包括 `MTEIndustrialMixer`、`RecipeMaps`、单方块／蒸汽基类和原生 MUI2 GUI。GTNL 参考范围见[单方块多流体输出](../references/GT-Not-Leisure参考索引.md#单方块多流体输出)。本轮 `spotlessApply compileJava processResources` 已通过；随后按用户补充授权执行 `spotlessCheck runClient`，日志确认格式检查通过，启动进程及游戏窗口已确认属于本项目，窗口截图显示已进入存档。客户端保持运行；本次尚未实际核验搅拌机 GUI、多流体物料守恒、堵塞、抽取及重载，不以启动或存档画面替代机器功能验收。

## ME输出总成

- 实现为 `common/machine/hatch/MEOutputAssembly.java`，继承 GT 原生 ME 输出仓；`MEOutputItemView` 是物品输出接口视图，不是第二个 MTE。实际仓室保留在原生流体输出仓列表，物品／流体 provider 共用主仓室的 ME 节点。原有 GT 多方块兼容注入不变。
- `client/gui/MEOutputAssemblyGui.java` 按“物品缓存标题、数值、控件；流体缓存标题、数值、控件”逐组自上而下排列；标题 12 像素、可换行容量 20 像素、控件行 18 像素，主面板高度为 230 像素，底部原生内容不与缓存区重叠。控件行仅设置 `crossAxisAlignment(CENTER)` 对齐行内控件，不能设置 `verticalCenter()`：MUI2 的该方法会设置 `topRel(0.5f)`，使控件行退出外层纵向 Flow 的正常布局。两组设置保留各自的元件槽、缓存／检查开关、优先级和刷新间隔。
- WAILA 普通正文先显示流体容量和物品容量，两行连续但不拼接；随后显示流体缓存明细、物品缓存明细、GT 原生“刷新至 ME”提示，最后显示其他仓室信息。刷新提示文字由 GT 流体 provider 原样生成，只调整其显示位置到两类缓存之后；不合并物品刷新周期或倒计时。高级正文保留原生流体存储元件内容，紧接物品存储元件标题与明细。服务端复用物品 provider 的原生 WAILA 序列化，将明细保存在 `betterexperienceItemWaila` 独立节点，避免与流体 provider 的 `stacks`／`stackCount` 等同名字段互相覆盖。名称在客户端按原始物品 NBT 本地化，数量读取长整型 `Amount` 并用 GT 原生列表样式显示；各列表沿用原生最多 10 类、按数量降序及省略数量提示。物品空缓存、元件标题和省略数量使用项目中英语言键。
- `MachineRecipes.registerMEOutputAssemblyRecipe()` 在 load-complete 注册组装机配方：一个 `ItemList.Hatch_Output_Bus_ME`、一个 `ItemList.Hatch_Output_ME` 和 `Materials.GlueAdvanced.getFluid(5_000)`，HV 配方电压、20 秒，产出一个总成；不受 TST 是否加载影响。
- 蒸汽基类的原生 `getOutputBusses()` 覆写只返回蒸汽总线，不会经过 `MTEMultiBlockBase` 上的物品视图注入；原成型检查又只看实体总线集合，两者共同遗漏总成。`BGTESteamMultiblockBase` 现将有效流体输出仓中的总成物品视图去重加入输出列表，成型检查也使用该列表，保留普通／蒸汽总线及原生流体路径。物品视图同时供输出空间检查和实际产物提交使用，未伪造实体总线。
- 参考范围与依赖版本见 [ME输出总成与蒸汽输出接口](../references/GT-Not-Leisure参考索引.md#me输出总成与蒸汽输出接口)。本轮未运行编译或游戏，配方展示、GUI／WAILA 渲染、单总成成型及双产物输出仍需运行验收。

## 初始化与注册

电力过胶机 `LatexRecipes` 的 LV–UEV 十档制造配方统一使用 `OrePrefixes.circuit.get(tier)` 描述等级电路矿辞，包括 HV／EV／IV 的两种合成橡胶分支，共十三条配方；不通过 `GTOreDictUnificator.get(OrePrefixes.circuit, ...)` 获取并锁定“任意 XX 电路板”占位物品栈。蒸汽过胶机仍使用指定的真空管。单元毁灭者电解机与搅拌机已使用相同的矿辞描述，无需改动；GT5U `.265` 的 `GTModHandler` 会将 `ItemData` 转为矿辞名称交给 `GTShapedRecipe`，不是只匹配矿辞首个物品。只读参考 GTNL `CraftingTableRecipes.java` 的 `LargeCircuitAssembler` 注册方式，未进行游戏内电路替代合成验收。

机器物品统一追加青色 `BetterGTExperience` 署名：`ClientProxy.init` 先调用公共机器注册，再遍历 `BGEMachineList`，通过 `isRegistered()` 跳过缺少 TST 时未绑定的条目，并使用已有 GTNHLib 的 `AnimatedTooltipHandler` 注册物品 Tooltip。匹配物品和元数据、忽略 NBT，覆盖多方块控制器、各等级单方块和 ME 输出总成；不影响 GT 原机，不更改原有 TST 来源说明，不在结构页追加署名。新增并绑定的枚举条目自动纳入。新版 GT 的 `toolTipFinisher(String...)` 已忽略作者参数，地狱接口改为无参收尾；版本与参考入口见 [Tooltip 与仓口](../references/GT-Not-Leisure参考索引.md#tooltip-与仓口)。尚未进行游戏内显示验收。

单元毁灭者电解机的储罐材料要求开发客户端加载 BuildCraft Factory 与 Iron Tanks。`dependencies.gradle` 已用 `runtimeOnlyNonPublishable(gtnhDev("BuildCraft"))` 和 `runtimeOnlyNonPublishable(gtnhDev("Irontanks"))` 显式补齐，版本跟随当前整合包清单，不新增编译期直接引用或发布依赖。配方注册前检查储罐、钢化玻璃和原机物品是否存在；缺失时记录等级与材料并跳过该档，避免将空材料交给 GT5U。GT5U 的注册返回值也按档记录，但成功返回只表示 API 接受，不代表 NEI 或实际合成已验收。

`preInit` 注册本项目 GTNHLib 配置；`init` 通过 `src/main/java/com/day/betterexperience/registry/MachineLoader.java` 注册机器并绑定 `BGEMachineList`。机器 ID 沿用用户确认的 `32200` 起始编号：两台 TST 增强机器占 `32200`、`32201`，无 TST 时仍保留空位，蒸汽电解机和后续机器的 ID 不移动，不自动改号。

机器和配方入口分别使用 `Loader.isModLoaded("TwistSpaceTechnology")`；TST 专属构造与配方隔离在 `registerTSTMachines(int)`、`MachineRecipes.registerTSTRecipes()` 中，并标记 Forge `@Optional.Method`。缺失 TST 时不构造两台增强机器、不绑定其模板，也不读取原机物品或注册对应配方；其他机器和配方照常注册。做法与版本边界见 [GTNL 可选模组集成](../references/GT-Not-Leisure参考索引.md#可选模组集成)。

`BGEMachineList` 只保存模板副本，读取返回独立物品栈，拒绝未绑定读取、重复绑定及无效数量。`loadComplete` 中的 `registry/MachineRecipes.java` 注册增强地狱接口装配线配方、增强光量子掌控者组装机配方和蒸汽电解机合成台配方；前两项仅在 TST 存在时执行。不修改 TST 原机配方。未进行有／无 TST 的游戏启动验收，开发运行 classpath 默认仍含 TST。
